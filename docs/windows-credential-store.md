# Windows testing credential store — implementation, not provisioning

This stage implements the local encrypted bundle proposed in the
[testing connection boundary](testing-connection-boundary.md). The PowerShell
[module](../proposals/application-storage/local-secret-store.psm1) is quarantined:
importing it creates nothing. No app, startup, driver or provisioning script calls
it. There is no database connection or real password generated by this increment.

## Storage contract

PowerShell 7.4+ on Windows only, non-production APP_ENV/NODE_ENV, explicit
`reviewed-gg-livestream-testing` acknowledgement, and an explicit absolute checkout
path are required. Trusted operator code supplies that path; no website input may
control it. The only destination is `<checkout>/.local-secrets/ggs-testing-storage.dpapi`,
already excluded from Git. No credential is placed in environment variables.

The bundle schema accepts only version 1, the exact testing project, the two exact
pooled login names and distinct 64-character lowercase hex passwords. Admin roles,
extra keys, shared secrets and other targets are rejected before writing anything.
The later provisioning operation must generate cryptographically random passwords;
shape validation alone does not prove entropy.

`Save-GgsTestingCredentialBundle` validates before writing, creates a secret
directory with protected ACLs at creation, and accepts an existing directory only
if its ACL already matches. Directory and file owner must be the current Windows
SID; only that SID and SYSTEM receive explicit FullControl. Inherited or extra
allow/deny rules are refused, not silently repaired. Existing bundle files are
never overwritten. Paths through reparse points, junctions or hard links are
refused; no other user's profile or system trust configuration is changed.

DPAPI CurrentUser protects the JSON bytes with fixed project/version entropy.
Only ciphertext is written to a unique, exclusively opened, restricted pending
file. It is flushed to disk and decrypted/validated for read-back before a
no-overwrite rename to the final filename. Final ACL/decryption are verified
again. An operation's own pending file is removed after ordinary failure, with
its exact parent/name checked. After process/power interruption, a pending file
may remain; do not adopt or delete it without a reviewed recovery operation.
There is no automatic credential rotation or partial-bundle overwrite.

`Invoke-GgsWithTestingCredentials` revalidates context, paths and ACLs, decrypts
only for a trusted in-process Consumer, then suppresses success-stream returns.
It replaces failures with one generic message, never returning driver/consumer
diagnostics or the bundle. Consumer code **must not** log, print, transcript,
write to other streams, or transmit credentials except to its separately approved
database destination. This is a local programming API, not an interactive command
to paste secrets into. A future operator bridge needs its own review; no such
bridge or app credential loader exists yet.

Mutable plaintext byte buffers are cleared in finally blocks; managed JSON strings,
PowerShell error history and consumer memory cannot be guaranteed erased. Run
real handling in a dedicated non-transcribed process and do not reuse a general
interactive session. CurrentUser DPAPI does not defend against malware/processes
under the same Windows identity or a privileged administrator. The directory's
parent must be trusted; checks do not promise protection against a malicious
same-user process racing filesystem operations. The bundle is not a portable
deployment secret store or a backup/recovery mechanism for another account.

## Twelve Windows tests

The [fixture suite](../tests/windows/local-secret-store.test.ps1) generates only
fictional repeated-character passwords under unique temporary directories. It
checks real DPAPI roundtrip, ciphertext-only disk contents, owner/SYSTEM ACLs,
no overwrite, invalid inputs/production/acknowledgement/path denial, unsafe
directory refusal without repair, corruption/truncation, loosened ACL refusal,
junction and hard-link refusal, and generic consumer failures/return suppression.
It clears only its checked fixture tree and refuses cleanup across reparse points.

Run `pwsh -NoProfile -File tests/windows/local-secret-store.test.ps1` under the
normal Windows identity. A restricted runner identity excluded by the deliberately
tight ACL can fail even for fictional data; do not broaden production ACLs to make
that runner pass. CI has a separate **Windows credential storage tests** job on
windows-2025, using no project secrets and installing no dependency. Missing Windows
support fails rather than silently skipping. There are 275 tests across four jobs:
the existing 263 plus twelve Windows cases. Tests do not prove cross-user DPAPI
denial by creating another Windows account, nor real database authentication.

## Exact later login setup — proposed, not executed

Target remains only GG-livestream testing, `rchxnmpsxfbsicthasxn`. Proposed roles:

| Identity               | Inherited group  | Private routine authority        |
| ---------------------- | ---------------- | -------------------------------- |
| ggs_pilot_intake_login | ggs_pilot_intake | submission only                  |
| ggs_pilot_review_login | ggs_pilot_review | owner list/history/decision only |

Both start **NOLOGIN**, NOSUPERUSER, NOCREATEROLE, NOCREATEDB, NOREPLICATION,
NOBYPASSRLS. Membership must have INHERIT true, SET false, ADMIN false. No other
group, ownership/executor membership, schema CREATE or direct table grant is
proposed. Stop on an existing name; never replace or grant additional privileges
to make a test pass. These are database service identities, not Auth users.

Fresh read-only preflight found no proposed login names, no owner configuration,
and no schema CREATE privilege for the entry groups. Existing database defaults
permit **CONNECT and TEMP**. A new login would inherit that baseline as well as
its entry group. This is not a new explicit TEMP grant, but it must be disclosed
in the later setup approval. Do not claim TEMP is denied or change PUBLIC grants
globally without a separate impact review. Permanent schema creation remains
unavailable under the observed grants. Recheck defaults at execution time.

The later secure-handoff operation must generate independent random 32-byte
secrets, set the passwords without exposing values in output/arguments/logs, and
save/read back the encrypted bundle before enabling either LOGIN. If any handoff
step fails, leave new roles unable to log in and report exact safe state. Enabling
LOGIN, authenticated role/privilege checks and cleanup/recovery must be specified
in that operation's explicit approval. Never automatically DROP roles/data or
overwrite a bundle after partial success; reconcile state first.

This stage supplies only the tested local store and review contract. The operator
provisioning/handoff bridge and real authenticated smoke test are **not yet
implemented or authorized**. A code merge does not create logins or approve real
credential storage. Owner seed, synthetic hosted writes, real applications,
invitations, admission, cleanup jobs and deployment remain later separate gates.
